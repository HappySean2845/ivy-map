# 上线与对外说明

> 本项目**没有现场路演**，交付物就是一个线上可访问的站点。本文取代原来的路演讲稿。

---

## 1. 最大的变化：没有人在旁边解说

原来的 3 分钟讲稿，本质是让人肉去补界面没说清的部分——「战报报的是 offer 数，一个孩子能拿七八个」这句话，是**讲出来的**，不是界面上写的。

线上没有这个人。**首屏必须自己把那 3 分钟讲完，而且访客只给你 5 秒。**

这不是文案润色的问题，它改变了功能优先级：

| 现场路演时 | 线上时 |
|---|---|
| 默认空白地图，等演示者点击 | ❌ 空白 = 访客不知道要干嘛，直接走 |
| 口径说明可以口头讲 | ✅ 必须内嵌在界面上 |
| 滑杆由演示者拖给你看 | ✅ 必须让访客自己发现它值得拖 |
| 纠错入口是「演示保险」 | ✅ **真实家长会来，真的会发现错** |
| 免责声明是合规摆设 | ✅ 长期挂着，是真的法律边界 |
| 断网预案 | ❌ 不需要了 |
| 录屏备份、现场应急 | ❌ 不需要了 |

## 2. 讲稿 → 界面的映射

原讲稿的每一段，现在都得在界面上找到承载物。**这张表是 US-1.0 的需求来源。**

| 原讲稿段落 | 线上由什么承担 |
|---|---|
| 问题陈述（「所有工具都在回答大学好不好」） | 首屏主标题 + 一句副标题，说清这是**反着用**的 |
| 双屏地图 | **默认已选中一所大学，热力已经亮着**——绝不能是空白等点击 |
| 滑杆（核心高光） | 载入后自动演示一次拖动 + 旁边常驻一句「为什么会变」 |
| 可行性闸门 | 表单默认折叠但显眼，带一句「先看看你报不报得了」 |
| 择校杠杆率 | 大学画像卡上常驻；判定为「低」时文案更醒目 |
| 护城河 / 方法论 | 「关于」页 + 本文 §4 的 FAQ |

## 3. 上线检查清单

### 内容自解释
- [ ] 首屏 5 秒内能看懂这是什么、和排名网站有什么不同
- [ ] 落地即有默认选中的大学 + 城市 + 赛道（本次为 **剑桥 × 上海 × A-Level**），榜单已有内容
- [ ] 首屏能看出「为什么默认是剑桥」——主线口径干净这件事要说，否则会被当成随便挑的
- [ ] 滑杆的价值无需交互即可感知（自动演示 / 前后对比 / 明确提示，三选一）
- [ ] 「什么是 offer 膨胀」入口在首屏可达

### 数据与合规
- [ ] 每个录取数值可点开看到来源链接，链接可打开
- [ ] 口径标注（人数 / offer / 估算）全站可见
- [ ] 免责声明在页脚与分享长图两处呈现
- [ ] 纠错入口可用，表单能收到提交

### 可用性
- [ ] 手机上能完整跑完主线（**主要流量来自微信里点开链接**）
- [ ] 任意筛选组合刷新后状态保持
- [ ] 空结果有具体建议，不是空表
- [ ] 分享链接在别人设备上打开，看到的是同一个视图

### 上线本身
- [ ] 生产域名可访问，无构建告警
- [ ] `<title>` 与描述写好（微信分享主要读 title）
- [ ] OG / Twitter meta 完整，非微信平台分享有卡片
- [ ] 埋点在跑，能看到访问与关键动作

> **微信分享卡片的真话**：自定义微信分享卡片需要 JS-SDK + 认证公众号，本次做不到。能做的是把 `<title>` 写好、页面靠前放一张合适的图。别在提交说明里承诺微信富卡片。

## 4. FAQ（放「关于」页，也可直接用作提交说明）

### 这和那些留学排名网站有什么不一样？

方向是反的。排名网站回答「这所大学好不好」，我们回答「**想去这所大学，该上哪所高中**」。

对一个初二孩子的家长来说，选大学是三年后的事，他今年唯一能动的杠杆是选高中。

### 你们的榜单凭什么比学校自己发的战报准？

修正了两件事。

**第一，offer 膨胀。** 战报报的是 offer 数，一个孩子能同时拿七八个。「30 枚藤校 offer」可能只对应 6 个人。我们折算成人头，并且标注哪些是折算过的。

**第二，没有分母。** A 校三年送 15 个进剑桥，B 校送 8 个——但 A 校每届 180 个毕业生，B 校只有 48 个。人均算下来 3.0% vs 5.8%，**B 校几乎是 A 校的两倍**。

界面上那个滑杆，就是这两个视角的切换开关。

### 为什么首页默认是剑桥，不是哈佛或藤校？

因为**只有英国方向的数字是点名到校的**。

国内学校的升学战报总会单独列出「牛津 X、剑桥 Y」——那是招牌。但美国方向报的是档位：「藤校 12 枚」「US Top 10 共 23 人」，**几乎没有学校会写「布朗 2 人」**。

要做一个「布朗的生源校榜单」，就得把那 12 枚藤校按某种比例拆到具体学校头上。**那是编造，我们不做。**

还有一层：英国走 UCAS，一人一份申请、最多 5 个志愿，牛津和剑桥只能选一个。所以「剑桥 4 枚」就是 4 个人头，**根本不存在 offer 膨胀**，也不需要折算。

美国方向仍然收录，只是它的呈现形态还在定（见「关于」页的规划）——**但无论怎么定，我们都不会把档位数字拆到单校。**

### 数据从哪来？可信吗？

三层来源，每条都标了等级：学校官方战报和升学报告是 L1，教育媒体年度汇总是 L2，公开统计推断是 L3。

**每一个数字都能点开看到来源链接、发布日期和等级。** 没有来源的数据不允许进入产品——这是构建时强制的，不是「尽量」。

### 分母（毕业生数）拿不到怎么办？

显示「—」，不是 0。该校在概率排序下降权并标注「分母缺失」。

**我们不猜分母。** 分母是这套算法的地基，猜分母等于伪造结论。

顺带说，这也是最难拿的字段——大多数学校只报喜不报分母。

### 会不会推荐我去一所我根本报不了的学校？

不会，这正是「可行性闸门」要解决的。填入孩子的国籍、户籍和年级，报不了的学校会自动置灰**并写明具体是哪一条不符合**——因为户籍能想办法，国籍不能。

### 你们是不是在贩卖教育焦虑？

判断正相反。焦虑来自信息不对称——家长不知道 offer 数是灌水的，不知道要看分母，不知道自己压根没资格报名。

而且系统会主动告诉你「这所大学的录取分散在一百多所高中，**择校杠杆低，钱和精力建议花在别处**」。一个愿意劝你别花钱的产品，很难说是在卖焦虑。

### AI 会不会编数据？

编不了，**模型根本碰不到数字**。它只把「杭州、初二、IB、预算 25 万」这句话解析成筛选条件填进筛选器，你看得见它填了什么，也能直接改。检索和排序全程确定性，和你手动点筛选器走的是同一条路。

### 数据错了怎么办？

每所学校页面有「数据有误？」入口。提交需要附来源链接，我们人工核实后更新并标注更新日期。

**线上产品最怕的就是错了没人告诉你**，所以这个入口是认真的，不是摆设。

### 这是什么规模的项目？

一个非全职的短周期项目，约 30 小时/人。技术上就是一个 JSON 文件加一个静态网页——**护城河从来不在技术上，在数据和口径上**。

## 5. 线上问题处置

| 情况 | 处理 |
|---|---|
| 学校方指出数据有误 | 优先核实来源，属实立即修正并标注更新日期。**不争辩、不拖延**——纠错速度就是可信度 |
| 数据被质疑造假 | 指向该数值的来源链接。可溯源存在的意义就是这一刻 |
| 站点挂了 | 纯静态 + CDN，基本只可能是构建问题；回滚到上一次部署 |
| 流量突增（被转发到家长群） | 静态站在 CDN 上，扛得住。**这也是当初不做后端的收益之一** |
| 有人要求下架某校数据 | 数据均来自公开信息且标注来源；先沟通核实，确有错误则改，无错误则说明来源。必要时可隐藏该校并记录原因 |
| 家长问「为什么没有布朗/某藤校的榜单」 | 照实说：战报只报「藤校 N 枚」，拆到单校就是编造。**不要用「数据还在补充中」搪塞**——这是方法论上的选择，不是进度问题，说清楚反而加分 |
| 学校方问「我们美国方向明明很强，为什么榜上看不到」 | 同上，并主动请对方提供分校、分赛道的公布口径数据。**这正是数据飞轮该转起来的地方** |
