# 数据来源、采集流程与合规边界

> 配套 [`PRD.md`](../PRD.md) §11、§14。**数据是本项目的关键路径，也是唯一真正的护城河。**

---

## 1. 置信分层

每条数据入库时必须打上等级。等级决定展示优先级与 UI 徽章。

| 等级 | 来源类型 | 举例 | 权重 |
|---|---|---|---|
| **L1** | 官方一手 | 学校官网/官微发布的升学战报、学校年度升学报告 PDF、学校招生简章 | 1.0 |
| **L2** | 权威二手 | 主流教育媒体的年度汇总、行业机构公开年报 | 0.7 |
| **L3** | 推断/众包 | 公开论坛统计、由 offer 口径折算而来的估算值、用户提交待核实数据 | 0.4 |

**规则**
- 同一 `(school, university, year, track)` 有多来源时，**全部保留**，展示取最高等级；等级相同但数值冲突时，UI 标注「多来源不一致」并列出各来源数值。
- 经 offer→人数折算的记录，等级**强制下调一级**（见 [`scoring.md`](scoring.md) §3）。
- **无 `source_id` 的记录不得入库。** 这条从建表就用外键约束死，不靠自觉。

## 2. 采集优先级

按「可信度 × 获取成本」排序，从上往下做：

1. **学校招生简章 / 官网升学页**（L1）—— 门槛数据的唯一权威来源，必须逐校人工核对。
2. **学校年度升学报告 PDF**（L1）—— 少数头部学校发布，含毕业生数与去向分布，**是密度分母的最佳来源**，拿到一份价值极高。
3. **学校官微升学战报**（L1）—— 覆盖面最广，但绝大多数是 offer 口径，需折算并标注。
4. **教育媒体年度汇总**（L2）—— 用于交叉验证与补缺，不作为唯一来源。
5. **公开论坛/社群统计**（L3）—— 仅用于填补空白，且必须在 UI 上明示等级。

> **优先抢 §2.2 的年度升学报告。** 毕业生数（`Grads`）是整个密度算法的分母，而它恰恰是最难拿的字段——大多数学校只报喜不报分母。谁先把分母补齐，谁就拥有了别人算不出来的指标。

## 3. 录入流程（黑客松版）

### 3.1 工具

共享表格（Google Sheets / 飞书表格）→ CSV 导出 → `import.py` 灌进 SQLite。

**不要一开始就写录入后台。** 48 小时里，表格的协作效率远高于任何自建 CRUD 界面。

### 3.2 表格列（与 `admission` 表严格对齐）

```
school_name | university_name | year | track |
admits_count | offers_count | count_basis |
source_url | source_type | source_published_at | confidence | 录入人 | 备注
```

### 3.3 两条硬规则

1. **每行必须有 `source_url`。** 没有链接的数据一律不录——哪怕你确信它是对的。
2. **`count_basis` 不许留空。** 只有 `admits` / `offers` / `estimated` 三个值。看不出是哪种口径的数据，宁可不录。

### 3.4 交叉核对（H32–H40）

随机抽 20 条，由**非录入人**回溯 `source_url` 验证数值。错误率 > 5% 则该批次全量重核。

## 4. MVP 数据范围

### 4.1 大学（10 所）

优先 8 所藤校 + 2 所中国家庭高关注度院校（如 NYU、UC Berkeley）——后者的作用是提供 **Leverage 低**的对照组，让「不必折腾」的叙事有实例支撑。

### 4.2 高中（20 所）

| 城市 | 数量 | 覆盖要求 |
|---|---|---|
| 上海 | 8 | 三赛道齐全；含公办国际部、民办国际化学校、外籍人员子女学校各至少 1 所 |
| 北京 | 5 | 含公办国际部 ≥ 2 |
| 深圳 | 3 | 含 A-Level 强校 ≥ 1 |
| 广州 | 2 | — |
| 杭州 / 南京 | 2 | 用于验证「非一线也有路径」的叙事 |

**为什么必须覆盖三种学校性质**：这三类的准入门槛完全不同（外籍要求、中考成绩要求、户籍要求），是可行性闸门功能的演示前提。只录民办国际化学校，闸门功能就没东西可演。

### 4.3 年份

近 3 届（2023 / 2024 / 2025 届）。

### 4.4 门槛数据（20 所 100% 填齐，不允许留空）

```
nationality_required | hukou_required | entry_grades |
exam_type | application_window | tuition | boarding | notes
```

确实查不到时填 `unknown` 并在 UI 显示「门槛信息待补充 + 反馈入口」，**不得留空或猜测**。

## 5. Demo 主线数据优先级

时间不够时，按此顺序保证完整性：

| 优先级 | 范围 | 说明 |
|---|---|---|
| **P0** | 布朗大学 × 上海 × IB/AP/A-Level 全部相关学校 × 3 年 | Demo 主线，必须 100% 完整含门槛 |
| **P1** | 其余 7 所藤校 × 上海 + 北京 | 保证切换大学时不空 |
| **P2** | 2 所对照大学（用于演示 Leverage 低） | 反直觉叙事的实例 |
| **P3** | 深圳 / 广州 / 杭州 / 南京 | 演示城市筛选 |

**任何时候都不要为了铺广度而牺牲 P0 的完整性。** 评委只会走一遍主线，主线上一个空数据比十个城市缺失更致命。

## 6. 合规边界

### 6.1 只用公开信息

全部数据来自学校主动公开发布、公开媒体报道、公开行业报告。

**不采集、不存储任何学生个人身份信息**——录取数据一律以「学校-大学-年份」的聚合计数存在，数据库里没有一行是关于某个具体孩子的。

### 6.2 尊重来源

- 遵守目标站点的 `robots.txt` 与服务条款；有官方公开数据接口的优先走接口。
- 采集频率保守，不对来源站点造成压力。
- 引用媒体/机构报告时保留出处与链接，不去除署名。

### 6.3 更正机制

每所学校页面提供「数据有误？」入口。校方或家长提交的更正进入审核队列，核实后更新并标注更新日期。

**这不只是合规动作**——它是数据飞轮的起点：学校为了自己的排名会主动来补数据。

### 6.4 v2（华尔街地图）的额外约束

投行 Target School 数据**不做个人职业档案抓取**（LinkedIn 等平台的 ToS 明确禁止，且涉及个人信息）。改以：

- 各机构公开发布的校招报告
- 专业机构（如 College Transitions）的年度公开报告
- 行业论坛的公开年度聚合统计

三类聚合来源为主。这样既规避风险，也不影响榜单层面的结论——我们要的是「哪些学校进得多」，不是「谁进去了」。

### 6.5 表述红线

全站不得出现：

- ❌ 「录取概率」「录取率预测」「保录」「冲藤成功率」等预测性表述
- ❌ 任何形式的排名商业化（付费改排序）
- ❌ 对具体学校的主观褒贬

只呈现**历史事实**与**统计口径**。这既是合规要求，也是产品可信度的来源。

- [ ] 所有折算记录的 `confidence` 已下调

- [ ] 20 所高中门槛字段 100% 填写（含 `unknown`）
- [ ] 抽检 20 条，错误率 < 5%
- [ ] Demo 主线（布朗 × 上海）数据 100% 完整
- [ ] 免责声明已在页脚与导出物中呈现
