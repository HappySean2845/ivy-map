# 设计系统

> 配套 [`PRD.md`](../PRD.md)。**这是一份约束，不是灵感板。** 所有组件按此实现，有冲突以本文为准。

---

## 0. 核心论点：学术风不是审美偏好，是可信度的载体

产品的第一原则是「每个数字都要有出处，宁可标数据不足，不可编造」（PRD 原则 §5.1）。

**学术出版物的视觉语言，存在的全部目的就是表达「我说的话你可以去查」** —— 引注、脚注、参考文献、表格、图注、口径说明。这套语言和这个产品要说的话是同一件事。

由此得到一条可执行的判断标准：

> **任何让页面更像「App」而不是「研究报告」的东西，都在削弱可信度。**

渐变、玻璃拟态、大圆角卡片、悬浮阴影、emoji 装饰、霓虹深色、弹跳动效——这些不是「不好看」，是**和产品要传达的东西相反**。

## 1. 字体

**不加载任何中文 web font。** 中文字体动辄几 MB，而主要流量来自微信里点开链接的移动端——等不起。

```css
--font-serif: "Songti SC", "STSong", "SimSun", "Noto Serif CJK SC", "Source Han Serif SC", Georgia, serif;
--font-sans: -apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", "Segoe UI", "Helvetica Neue", sans-serif;
--font-mono: ui-monospace, "SF Mono", "Cascadia Mono", Menlo, monospace;
```

| 用途 | 字体 | 理由 |
|---|---|---|
| 标题、大学名、章节头 | **衬线（宋体）** | 中文出版物的正统。Mac 是宋体、Win 是中易宋体，全部系统自带，零加载 |
| 正文、表格、控件 | **无衬线（苹方/雅黑）** | 屏幕可读性 |
| 数字 | 无衬线 + `tabular-nums` | 表格里数字必须对齐 |
| 来源 id、代码 | 等宽 | |

**宋体标题 + 黑体正文是中文书籍、期刊、年报的经典配置。** 国内读者一眼就有「正经东西」的感觉，而这正是我们要的。

数字一律 `font-variant-numeric: tabular-nums;`——榜单重排时数字不该左右跳动。

## 2. 色彩

### 浅色（默认）

```css
--paper:      #FBFAF7;  /* 底。暖白，不是纯白——纯白是网页感，微暖是纸感 */
--paper-sunk: #F4F1EA;  /* 次级底：表头、折叠区 */
--ink:        #1A1A18;  /* 正文。不是纯黑 */
--ink-muted:  #6B6862;  /* 次要信息、图注 */
--ink-faint:  #9A968E;  /* 占位、禁用、「—」 */
--rule:       #E3DFD6;  /* 分隔线 */
--rule-strong:#C9C3B6;  /* 表头下方的粗线 */

/* 主色：靛青。数据、选中、链接、热力 */
--accent:      #1D5B6E;
--accent-deep: #123E4C;  /* 热力最深 / hover */
--accent-soft: #DCE8EC;  /* 极淡底：当前行、选中省份的浅态 */

/* 信号色：朱红。只在「需要注意」时出现，见下 */
--signal:      #9E2B25;
--signal-soft: #F0E2E0;
```

### 深色

```css
--paper:      #16151A;
--paper-sunk: #1E1D23;
--ink:        #EDEAE3;
--ink-muted:  #9A968E;
--ink-faint:  #6B6862;
--rule:       #2E2C33;
--rule-strong:#43404A;

--accent:      #6FB3C7;  /* 靛青在深色上要提亮 */
--accent-deep: #A5D2E0;
--accent-soft: #1B333C;

--signal:      #C9564E;
--signal-soft: #3A2523;
```

### 为什么是靛青

中文语境里青是文人色——青花、靛蓝、水墨的冷调。**沉稳、克制、有距离感，但不压迫**。配暖白纸底和宋体标题，出来的是年鉴和期刊的气质，不是 SaaS 的气质。

而且它和产品要说的话是一致的：我们不煽动，我们摆数据。

### 红色降级为信号色——这是本次配色的关键决定

朱红**不做装饰、不做品牌色**，只在这几种情况出现：

| 场景 | 为什么值得用红 |
|---|---|
| 「择校杠杆低，建议把精力花在别处」 | 这是产品最反直觉、最该被看见的一句话 |
| 不可申请（可行性闸门置灰的原因） | 家长最容易忽略、代价最大的一条 |
| 分母缺失 / 多来源不一致 | 数据诚信的警示 |
| 估算值（offer 折算而来） | 提醒这个数字经过了推算 |

**红色越稀有，出现时越有分量。** 满页面都是红，「别折腾」那句话就淹没了。

### 数据可视化

一律**单色阶**（纸色 → 靛青），绝不用彩虹色。热力图用靛青单色渐变。

需要第二个序列做对照时（比如「你的学校」vs「同城对标」），第二序列用 `--ink-muted` 的灰，**不要引入第三个颜色**。

## 3. 版式

**学术出版物没有阴影卡片。**

| 规则 | 做法 |
|---|---|
| 分区 | **1px 规则线**，不用阴影、不用彩色底块 |
| 圆角 | 最多 `2px`。按钮、输入框可到 `3px`。没有大圆角卡片 |
| 阴影 | **不用**。唯一例外是浮层（popover / 抽屉），且要极淡 |
| 表格 | 表格是主角。表头下 1px 粗线，行间 1px 细线，不用斑马纹 |
| 数字 | 右对齐 + `tabular-nums` |
| 留白 | 舍得留白，但靠**层级**制造密度，不靠堆间距 |
| 强调 | 用**粗体**，不用颜色（见 §5 截图约束） |

### 章节头的写法：像报告，不像 App

App 的写法是「点击地图选择大学」。报告的写法是：

```
IVY Map · 生源校研究
────────────────────────────────
剑桥大学 · 中国大陆生源校
2023–2025 三届加权 · 按人均密度排序
```

后者天然会先说清自己在讲什么，**直接降低了首屏自解释（US-1.0）的难度**。

## 4. 脚注式来源标注（本设计系统的核心机制）

**数值旁边跟一个上标标记，点击展开来源；页面底部有「资料来源」列表。**

就是论文引注的形式。

```
剑桥大学  33 人 ¹        ← 上标可点击
包玉刚    12 人 ⁽²⁾      ← 括号 = L2 权威二手
世外       7 人 ⁽³⁾ˀ     ← 带问号 = L3 推断/估算

─────────────────────────────
资料来源
1. 深国交官微《2025 届录取捷报》2025-05-15  [L1]
2. 腾讯新闻《牛剑录取风云榜》2025-02-05     [L2]
3. ……
```

### 置信等级用上标样式区分，不用彩色徽章

| 等级 | 标记 | 含义 |
|---|---|---|
| L1 | `¹` 实心数字 | 官方一手 |
| L2 | `⁽²⁾` 加括号 | 权威二手 |
| L3 | `⁽³⁾ˀ` 括号 + 问号 | 推断 / 众包 / 估算 |

**为什么比灰色小徽章好**：形式上直接对应产品第一原则；国内家长对「参考文献」有天然信任感；不占横向空间；**而且它让整个页面看起来像研究报告而不是工具**。

估算值（offer 折算而来）额外在数字后加一个 `≈`。

## 5. 两条硬约束

### 5.1 这个人群会截图发家长群

主用户的真实行为是**截图转发**，不是收藏链接。所以：

- **关键结论用粗体，不用颜色** —— 截图后、色弱、黑白打印都成立
- **来源标注必须在截图范围内**，不能靠 hover 才出现（移动端也没有 hover）
- 榜单的口径说明要跟着表格走，别放在页面顶部很远的地方——截一半就丢了

### 5.2 家长年龄偏大

- 移动端正文**不小于 15px**，表格数字不小于 15px
- 点击目标不小于 44×44
- 术语首次出现给中文解释（Feeder School → 生源校）
- 不用纯英文标签

## 6. 明令禁止

| ❌ | 为什么 |
|---|---|
| 渐变背景 | 报告不用渐变 |
| 玻璃拟态 / 毛玻璃 | 同上 |
| 大圆角卡片（> 4px） | App 感 |
| 悬浮阴影分区 | 用规则线 |
| emoji 装饰 | 削弱正式感（功能性图标除外） |
| 彩虹色阶 / 多色分类色 | 单色阶 |
| 霓虹深色主题 | 深色也是墨与纸 |
| 弹跳、缩放、粒子动效 | 唯一允许的动效见 §7 |
| 骨架屏闪烁 | 用静态占位 + 「加载中」文字 |

---

## 7. 动效：只有两处

1. **滑杆重排时的行位移** —— 帮助用户感知「排名变了」。`transform` 位移，180ms，`ease-out`。不能拖慢重排本身。
2. **US-1.0 的滑杆自动演示** —— 载入后自动拖动一次再回位，约 2 秒，缓动。用户一旦手动交互立即中止。

两处都必须尊重 `prefers-reduced-motion: reduce`——直接跳到终态，不做过渡。

其余一律无动效。hover 状态用颜色/下划线变化，不用位移。

## 8. 组件基调速查

| 组件 | 基调 |
|---|---|
| **FeederTable** | 学术表格。表头下粗线，行间细线，数字右对齐 tabular-nums，排名用衬线 |
| **WeightSlider** | 一根细轨 + 一个小圆钮。两端标签用小字。**不要做成花哨的自定义控件** |
| **地图** | 单色阶热力（纸→靛青）。省界用规则线色。选中省份填 `--accent` |
| **SourcePopover** | 移动端底部抽屉，桌面小浮层。内容排版像参考文献条目 |
| **DeepCard** | 四段用规则线分隔 + 衬线小标题，像报告的章节 |
| **可行性闸门** | 折叠态一行字 + 一个「填写」链接。展开是紧凑表单 |
| **分享长图** | 最像纸的一个界面。纸色底、宋体标题、表格、底部资料来源与免责声明 |
