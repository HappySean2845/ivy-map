# IVY Map · 常春藤择校地图

> 把「孩子该上哪所高中」这个问题，从家长的道听途说，变成一张可查、可比、可解释的数据地图。

留学圈所有工具都在回答「这所大学好不好」。但一个初二孩子的家长此刻能动的唯一杠杆，是**今年把孩子送进哪所高中**。

IVY Map 反着来：**点一所目标大学 → 反推出国内哪些高中真正在往那里送人 → 并告诉你，你家孩子报不报得了。**

---

## 三个差异化

| | 说明 |
|---|---|
| **修正口径** | 学校战报报的是 offer 数（一人多 offer）且不给分母。我们去重成人头、除以毕业生数，得到**人均命中率**。 |
| **「规模 ↔ 概率」滑杆** | 一个滑杆在「哪所送得最多」和「我家孩子命中率最高」之间切换——这两个问题的答案经常是反的。 |
| **可行性闸门** | 榜单第一名不一定你能报。填入国籍/户籍/年级，报不了的学校自动置灰并说明原因。 |

还有一个刻意反商业的功能：**择校杠杆率**。如果某所大学的录取分散在上百所高中，系统会直接告诉你「这所学校不太看你从哪来，钱和精力建议花在别处」。

## 本次范围

| | |
|---|---|
| 周期 | 2026-07-29 → 08-08（11 个日历日，**非全职**，约 30 小时/人） |
| 功能 | 30 条用户故事中交付 **20 条**（P0 16 + P1 4），其余转 P2 |
| 数据 | 30 所大学 × 40 所国内国际化学校 × 近 3 届 × **AP / IB / A-Level 三赛道**，门槛数据 100% 填齐 |

**范围判断的依据**：11 个日历日 ≠ 11 个工作日。按小时算只有约 30 小时/人，与一场标准 48 小时黑客松持平，所以功能范围必须收回去。

但 11 天有一个 48 小时没有的红利——**数据录入可以塞进碎片时间，不占用稀缺的连续编码时间**。所以：功能砍回 48 小时的量，数据放大到 2 倍。对这个产品来说，数据才是护城河。

## 技术栈

```
Next.js（App Router）+ Tailwind + ECharts + TypeScript，部署在 Vercel
```

**没有后端，也没有数据库。** 全量数据约 2,000 行、gzip 后 50–60KB，构建时打进 bundle，所有筛选、排序、滑杆重排、闸门过滤都在客户端完成。

这不只是图省事——滑杆每秒触发几十次重排，**走一趟 HTTP 手感就毁了，而手感就是那个功能的全部价值**。

唯一的服务端是 AI 解析用的一个 Route Handler，而它排在降级顺序第一位；砍掉后整个项目退化为纯静态站。

**线上交付下这个选择更划算**：静态站挂 CDN，被转发到家长群带来的流量高峰扛得住，且零运维。

数据质量由构建期的校验脚本保证（校验不通过则构建失败），详见 [`docs/design.md`](docs/design.md)。

## 数据与免责

数据来自学校官方公开发布、公开媒体报道及公开行业报告，均为**聚合计数**，不采集任何学生个人身份信息。

本项目不提供录取概率预测，不做保录承诺，不接受付费改排序。数据可能存在滞后或误差，不构成升学建议。详见 [`docs/data-sources.md`](docs/data-sources.md) §6。
